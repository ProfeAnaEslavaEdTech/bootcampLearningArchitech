WCAG 2.2 AA — Accessibility Audit Guide

Cómo auditar y verificar accesibilidad web · Proceso paso a paso · Código, herramientas y marco legal

WCAG 2.2 Accesibilidad 9 criterios nuevos Nivel AA EN 301 549 Ley 11/2023 ES
Marco legal: España — Ley 11/2023 (transpone Directiva UE 2016/2102; exige WCAG 2.1 AA como mínimo, buena práctica: WCAG 2.2 AA) · UE — Directiva 2016/2102/UE · EN 301 549 v3.2.1 (2021) · EE.UU. — Section 508 (Rehabilitation Act, revisada 2018) · Estándar técnico — WCAG 2.2 (W3C Recommendation, 5 oct 2023)
01¿Por qué WCAG 2.2 y no WCAG 2.1?

WCAG 2.2 (W3C, octubre 2023) añade 9 criterios nuevos sobre WCAG 2.1. Los más relevantes para diseño instruccional digital:

CriterioNivelQué exige
2.4.11 Focus Not ObscuredAA ✦El elemento con foco no queda completamente oculto por otro (p.ej. header sticky)
2.5.7 Dragging MovementsAA ✦Toda funcionalidad de arrastre tiene alternativa sin arrastre
2.5.8 Target Size MinimumAA ✦Área de toque ≥ 24×24 CSS px
3.2.6 Consistent HelpAA ✦El mecanismo de ayuda aparece en la misma posición en todas las páginas
3.3.7 Redundant EntryA ✦No solicitar información ya proporcionada en el mismo proceso
3.3.8 Accessible AuthenticationAA ✦No requerir test cognitivo para autenticarse sin alternativa

✦ = Criterio nuevo en WCAG 2.2 (no presente en WCAG 2.1)

02Principios POUR
  • Perceptible — La información puede percibirse por todos los sentidos.
  • Operable — Los controles y la navegación son accionables con teclado y puntero.
  • Comprensible — El lenguaje y el comportamiento son predecibles.
  • Robusto — El contenido funciona con tecnologías de asistencia actuales y futuras.
03Proceso de auditoría — 6 pasos
1

Preparación

Define el alcance (páginas únicas), anota la URL canónica, elige agente de usuario (Chrome + NVDA o Safari + VoiceOver), descarga WCAG Quick Reference.

2

Inspección automatizada (~30-40 % de problemas)

axe DevTools (extensión Chrome/Edge) · WAVE (webaim.org/wave) · Lighthouse (DevTools → Lighthouse tab). Exporta el informe.

3

Verificación manual con teclado

Tab / Shift+Tab · Enter / Espacio · teclas de flecha · verificar skip link, foco visible, sin trampa de foco.

4

Lector de pantalla

NVDA + Firefox (Windows, gratis) o VoiceOver + Safari (macOS/iOS). Navega por encabezados, links, formularios. Verifica alt text, aria-live, nombres accesibles.

5

Contraste de color

Colour Contrast Analyser (TPGi, gratis). Texto normal ≥ 4.5:1 · Texto grande ≥ 3:1 · Componentes UI ≥ 3:1.

6

Documentar hallazgos

Tabla: Criterio · Descripción · Impacto · Pasos para reproducir · Elemento HTML · Severidad · Recomendación · Estado.

04Correcciones más frecuentes

Skip Link — 2.4.1 Bypass Blocks (Nivel A)

ANTES — Fallo 2.4.1
<body>
  <nav>…nav completa…</nav>
  <main>…contenido…</main>
</body>
DESPUÉS — Conforme
<body>
  <a href="#main-content" class="skip-link">
    Skip to main content
  </a>
  <nav>…nav completa…</nav>
  <main id="main-content">…</main>
</body>

aria-live — 4.1.3 Status Messages (Nivel AA)

ANTES — Sin anuncio
<div id="panelHead"></div>
<!-- textContent cambia silenciosamente -->
DESPUÉS — Anunciado
<div id="panelHead"
     aria-live="polite"
     aria-atomic="true"></div>
<!-- VoiceOver/NVDA anuncia el cambio -->

Alt text — 1.1.1 Non-text Content (Nivel A)

<!-- Imagen informativa -->
<img src="grafico.png" alt="Gráfico: tasa de finalización 87% módulo 1">

<!-- Imagen decorativa (el lector la ignora) -->
<img src="deco.png" alt="">

06Ejercicio práctico
  1. Elige una URL de un proyecto e-learning o portfolio
  2. Ejecuta axe DevTools y exporta el informe
  3. Navega la página entera solo con teclado (sin ratón) durante 5 minutos
  4. Verifica el contraste de los 3 colores de texto principales
  5. Activa NVDA o VoiceOver y navega por encabezados
  6. Documenta cada hallazgo en la tabla del Paso 6
  7. Propón la corrección de código para los 2 problemas más graves

Criterio de éxito: Has identificado al menos 1 fallo Nivel A y propuesto su corrección con código antes/después.
