# ID Golden Deliverables

Package an instructional-design project as portfolio-grade deliverables that mirror the
industry "golden" models (design documents, storyboards, facilitator guides, project
pages). Keep Ana's standards: measurable objectives, honest Kirkpatrick framing, Zero-Gate
mastery on critical items, bilingual EN/ES, and Art. 50 AI disclosure.

## When to use
- Reorganizing or formatting existing course assets (scripts, decks, Rise exports) into a
  professional deliverable set.
- Writing a Design Document, Storyboard/Design Script, Portfolio Project Page, or a
  VILT/ILT Facilitator Guide.
- Delivering a project that contains a **3D demo/simulator** — always add the 3D fact sheet.

## Workflow
1. **Classify the delivery model** before choosing templates:
   - **E-learning (self-paced)** → use `references/design-document.md` (e-learning schema).
   - **VILT / ILT (instructor-led)** → use the VILT schema in `references/design-document.md`
     + `references/facilitator-guide.md`.
   - **Blended** (e-learning L2 + supervised practice L3/L4) → produce BOTH: the e-learning
     design document AND the facilitator guide with the L3/L4 checklists. State "Delivery
     method: BLENDED" explicitly.
2. **Always produce the Portfolio Project Page** (`references/portfolio-page.md`): Title,
   The Problem, Tools used, and linked deliverables. This is the index of the project.
3. **Produce the Design Document** in the matching golden schema (two-column table, dark
   header labels). Keep measurable Terminal/Enabling objectives and an Assessment Plan with
   the Zero-Gate rule and unlimited attempts on critical items.
4. **Produce the Storyboard / Design Script** per `references/storyboard-script.md`
   (slide-by-slide or screen-by-screen table: On-screen · Voiceover/Narration · Developer
   notes · Interactions/Assessment).
5. **For any 3D demo/simulator, append the 3D Demo Fact Sheet** (`references/3d-demo-factsheet.md`):
   technical spec, pedagogical spec, telemetry (xAPI statements + SCORM mirror + exports),
   KPI mapping, and **total production hours** as a production detail. This is MANDATORY
   from now on whenever the project includes a 3D demo.
6. **Output format**: deliver editable **Word (.docx)** files (Ana's design folder standard),
   built with the `docx` Node library (see her prior build scripts), unless she asks for
   another format. One file per deliverable; keep a consistent navy/white table style.
7. **Bilingual**: produce EN and ES where Ana asks; the golden portfolio models are English,
   so default the portfolio page and design document to English and offer ES.

## Non-negotiable standards (apply to every deliverable)
- **Honest Kirkpatrick framing**: an e-learning / browser 3D simulator measures the
  DECISION and the SEQUENCE (Level 2). Real fine motor skill is verified in supervised
  practice (Level 3) with an observation checklist; transfer is confirmed at Level 4
  (defect rate / line stoppages). Never claim the simulator measures motor skill.
- **Zero-Gate**: critical items require 100% (single-layer decision), unlimited attempts.
- **Art. 50 (EU) 2024/1689** AI-disclosure footer on every deliverable.
- **Measurable objectives** (Terminal + Enabling), aligned to the assessment.
- **Production detail**: include estimated production hours (by phase) on the project page
  and on the 3D fact sheet; label as estimate and adjustable.

See `references/` for the exact structure of each deliverable.
