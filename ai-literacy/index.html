Step 02 — Teach

Before RLHF: the base model

Every AI tool you use — ChatGPT, Claude, Copilot in Storyline — started as a base model. Understanding what a base model is (and is not) explains why RLHF had to be invented.

📖 What a base model actually does

A base language model is trained on hundreds of billions of words — books, websites, code, articles — using one simple objective: predict the next word (technically, token) given everything that came before.

Input: "The capital of France is" ↓ Model predicts highest-probability next token Output: "Paris" (probability: 0.94) "Lyon" (probability: 0.03) "Berlin" (probability: 0.01)

The problem with a pure base model for IDs

If you give a base model the prompt "Write a learning objective for slide 3", it might respond by generating more prompts that look like they belong in the same document — because that's statistically likely. It's not being unhelpful; it's doing exactly what it was trained to do: continue the text.

Base models also have no concept of "I shouldn't say this" or "the user wants a short answer." They produce whatever token sequence has the highest probability given their training data — including harmful, biased, or just plain wrong content — because probability ≠ accuracy or appropriateness.

💡
Key insight for IDs: When an AI tool gives you a plausible-sounding but factually wrong learning objective or quiz question, that's base model behavior leaking through the RLHF layer. The model predicts text that looks like a correct answer, not text that is a correct answer.
✍️ RLHF Phase 1 · 25 XP
Step 03 — Teach

RLHF Phase 1: Supervised Fine-Tuning

The first phase of RLHF turns the "next-word predictor" into something that at least tries to be helpful. This is where human trainers get involved for the first time.

📋 What happens in SFT

Phase 1 — Supervised Fine-Tuning (SFT)

Human trainers write thousands of high-quality prompt→response pairs. "Given this instruction, here is an ideal response." The base model is then fine-tuned (further trained) on these examples — it learns to imitate the style, format, and tone of a helpful assistant rather than continuing arbitrary text.

What SFT teaches the model

  • Respond to instructions, not just continue text
  • Use a conversational format with a clear answer
  • Decline some categories of harmful request
  • Structure long answers with headings, lists, steps

What SFT does NOT fix

SFT examples are expensive to create — you can only write so many. The model generalizes from those examples, but it still makes things up with confidence, still gets edge cases wrong, and still doesn't reliably know when it's uncertain. That's what Phases 2 and 3 address.

✅
ID parallel: SFT is like onboarding a new instructional designer by showing them your best past work. They learn your format and tone quickly, but they still need feedback loops — which is exactly what Phases 2 and 3 provide.
⚖️ RLHF Phase 2 · 25 XP
Step 04 — Teach

RLHF Phase 2: the reward model

This is the most important phase to understand as an ID — because the reward model is the mechanism that shapes what your AI tool thinks "good" means. And it has a specific, exploitable weakness.

📊 Building the reward model

Phase 2 — Reward Model Training

The SFT model generates several different responses to the same prompt. Human raters then rank these responses: "Response A is better than B, which is better than C." A separate neural network — the reward model — is trained to predict those human rankings. It learns what a human rater would prefer.

The ranking process, visualized

Prompt: "Explain SCORM in one sentence" Response A: "SCORM is a set of technical standards for eLearning..." Response B: "SCORM stands for Sharable Content Object Reference Model and is used in eLearning..." Response C: "SCORM is a format." Human ranking: A > B > C ↓ Reward model learns to score A higher than B or C

What the reward model actually captures

The reward model learns human preference, not objective truth. Humans tend to rate responses that are:

  • Confident-sounding → rated higher (even if wrong)
  • Well-structured with bullet points → rated higher
  • Appropriately detailed → rated higher
  • Hedged ("I'm not sure…") → often rated lower
⚠️
This is why AI tools hallucinate so confidently. The reward model was trained to prefer confident-sounding responses. So the optimized model learns to sound confident — even when it's generating plausible nonsense. As an ID, you must verify every fact an AI tool gives you, especially statistics, citations, and technical specs.
🔄 RLHF Phase 3 · 25 XP
Step 05 — Teach

RLHF Phase 3: optimization with RL

The third phase is where the model is actually trained to maximize its reward score. This is what makes it behave like an assistant — and where the most interesting failure modes emerge.

🎮 Reinforcement Learning loop

Phase 3 — RL Optimization (PPO)

The SFT model generates responses. The reward model scores them. The RL algorithm (typically PPO — Proximal Policy Optimization) adjusts the model's weights to produce responses that score higher. This loop runs thousands of times until the model is reliably producing high-reward outputs.

Model → generates response → Reward Model scores it ↑ ↓ Weights updated ← PPO algorithm ← score fed back

What comes out the other end

After all three phases, you have a model that:

  • Responds to instructions rather than continuing text
  • Structures answers in a format humans rate as helpful
  • Declines obviously harmful requests
  • Sounds confident and well-organized

📋 Instruction Following · 25 XP
Step 06 — Teach

What instruction following actually means

Instruction following is the AI capability that matters most for IDs using authoring tools and AI assistants. It's not about whether the model "understands" your intent — it's about whether it precisely obeys multi-part constraints without drifting.

🎯 The spectrum of instruction compliance

Instruction typeExampleHow well models follow it
Simple format"Give me a bulleted list"Very reliable
Count constraint"Write exactly 5 questions"Often drifts (6 or 4)
Bloom's level"At the Analysis level only"Inconsistent without examples
Persona"Write as a clinical trainer"Good for 1-2 turns, then drifts
Multiple constraints"5 MCQs, Bloom's Apply, under 20 words each"Drops some constraints
Negative instruction"Do NOT use the word 'leverage'"Often violates it

Why models fail complex instructions

RLHF trained the model on human preferences — but human raters in Phase 2 were usually comparing two complete responses, not checking whether every constraint was met. A response that hits 4 out of 5 constraints but reads well might score higher than a response that hits all 5 but is awkwardly phrased. The model learns to optimize for "sounds good" over "obeyed every rule."

🤖
OpenAI's instruction-following research found that models fail most often when: (1) instructions are ambiguous, (2) there are more than 3 simultaneous constraints, or (3) a constraint conflicts with what the reward model finds "natural." Newer models are significantly better, but the pattern holds.

What this means for ID prompts

The more constraints you stack in one prompt, the higher the chance something gets dropped. The fix is not to write better English — it's to restructure the prompt so constraints are explicit, numbered, and minimal.

⚠️ Failure Modes · 25 XP
Step 07 — Teach

Why AI fails: reward hacking & hallucination

Two failure modes you will encounter regularly as an ID. Understanding their root causes is what lets you design prompts and review processes that catch them.

🎯 Reward Hacking

Definition: The model learns to score high on the reward model without actually being helpful — it finds shortcuts the reward model didn't anticipate.

Examples you'll see as an ID

  • Sycophancy: The model agrees with you even when you're wrong. "That's a great learning objective!" (it's not at the right Bloom's level) — because agreement scored well in training.
  • Padding: Adds unnecessary preamble ("Certainly! Here's a comprehensive overview…") because human raters rated thorough-looking responses higher.
  • Confidence without knowledge: States facts it doesn't know with the same tone as facts it does know — because the reward model couldn't distinguish confidence-in-knowledge from confidence-in-fabrication.

🌀 Hallucination

Definition: The model generates plausible-sounding but factually false information, stated confidently.

Why hallucination is a specific RLHF artifact

A base model that's uncertain might just produce low-probability tokens or trail off. But RLHF trained the model that confident, complete-sounding answers score well. So when the model doesn't know something, it generates the most probable completion of a confident-sounding sentence — which is a fabricated but plausible answer.

⚠️
High-risk ID tasks: Asking AI to generate statistics ("what percentage of learners…"), citations ("cite a study on…"), regulatory details ("the GDPR article that covers…"), or product specifications ("what does Articulate Rise support…"). All are high hallucination risk. Always verify with primary sources.

Step 09 — Apply

Prompt design for IDs: making instruction following work

Now that you know how the model works, you can write prompts that work with its architecture instead of against it. Four principles that directly counteract RLHF failure modes.

✏️ Principle 1: Role + Task + Constraints + Format

Structure every significant prompt in four parts. This maps directly to what RLHF training taught the model to respond to.

[ROLE] You are an instructional designer specializing in compliance training. [CONTEXT] Audience: marketing employees, no legal background. Topic: GDPR data handling. [TASK] Write 3 learning objectives at Bloom's Apply level (not Remember, not Analyze). [FORMAT] Each objective must: start with a measurable verb, be under 20 words, avoid the word "understand."

Principle 2: Number your constraints

The model follows numbered lists more reliably than prose paragraphs. Three constraints buried in a sentence are easy to miss; three numbered bullets are much harder to ignore.

Your output must follow these rules: 1. Exactly 5 questions — no more, no less 2. Each question tests the Apply level of Bloom's taxonomy 3. Each distractor is plausible but clearly wrong on reflection 4. No question uses the word "which" as the first word

Principle 3: Give an example of what you want

Showing one ideal output is more effective than describing it in words. The model's SFT training makes it excellent at imitating demonstrated patterns.

Example of the format I want: Objective: Given a customer data request, the learner will apply the GDPR right-to-erasure process using the company intake form. Now write 2 more objectives in this exact format for these topics: - Data breach internal reporting - Consent withdrawal handling

Principle 4: Ask for self-checks

Appending "Check that each objective starts with a measurable verb" forces the model to re-read its own output against a specific criterion before it finishes — a lightweight version of chain-of-thought reasoning that catches the most common drift.

🔧
For Articulate 360 workflows specifically: When using AI to draft Rise 360 block content, always specify the block type ("write this as a labeled graphic caption, max 40 words"), the learner action ("what the learner should DO after reading this"), and a fact you want included. This anchors the output and makes verification easier.

AI in your Articulate 360 authoring workflow

Where AI genuinely accelerates ID work, where it introduces risk, and the minimum verification step for each task.

🗺️ AI-assisted ID workflow

The two-step rule for any AI-generated content

  1. Format check: Does the output match the structure and constraints you asked for?
  2. Fact check: Is every factual claim in this output verifiable from a primary source you trust?
💡
AI tools are best used as a first draft engine, not a final content producer. The ID's job shifts from "write from scratch" to "brief clearly, review critically, edit precisely." That's a genuine productivity gain — as long as the review step isn't skipped.
